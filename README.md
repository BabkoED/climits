# climits

Лимиты Claude в строке меню macOS. Те же цифры, что показывает `/usage`
внутри Claude Code, только видны всегда и без запуска Claude Code.

> **Статус:** первая версия. Логика разбора покрыта проверками (`./run-tests.sh`),
> сборка приложения идёт на настоящем macOS в CI - значок сверху показывает,
> прошла ли она. Если что-то не так на твоей машине, заведи issue.


## Что показывает

В строке меню - то, что выберешь сам: процент текущего окна, время до сброса,
недельный кап, лимиты по каждой модели (Opus, Sonnet, Fable), потраченное сверх
лимита в деньгах. Кружок слева меняется по самому нагруженному лимиту, даже
если в тексте показан другой - чтобы короткая строка не скрывала проблему.

Деньги, токены, столбики за неделю и темп в строку не попадают даже
включёнными: там места на три-четыре знака, и заняты они тем, что отвечает
на «работать дальше или подождать». Всё остальное живёт в выпадающем меню.
Нужны и в строке - `{money}` и `{tokens}` дописываются в «свой формат».

В выпадающем меню - все лимиты сразу: шкала, процент, время до сброса,
пометка `▸` у того, который упрётся первым. Отдельной строкой - расход сверх
лимита и персональный месячный потолок, если он задан.

**Два числа, а не одно, и это нарочно.** Процент считает Anthropic по всему
аккаунту - он полный, но не говорит, сколько это в деньгах или токенах.
Деньги и токены считаем мы - они точные, но видят только те машины, которые
мы читаем. Разошлись - значит работа идёт ещё откуда-то.

## Установка

Готовая сборка - в [релизах](https://github.com/BabkoED/climits/releases).
Ничего ставить и собирать не нужно. Отдельная инструкция для тех, кто просто
хочет поставить и пользоваться: [INSTALL.md](INSTALL.md).

1. Скачать `climits.zip`, распаковать
2. Перетащить `climits.app` в «Программы»
3. Первый запуск - **правый клик по приложению → «Открыть» → «Открыть»**

Третий шаг обязателен ровно один раз. macOS скажет, что разработчик не
подтверждён: приложение не подписано сертификатом Apple, потому что сертификат
стоит денег и выдаётся на человека. Обычный двойной клик после этого работает.

Кому привычнее командой:

```bash
xattr -dr com.apple.quarantine /Applications/climits.app
```

Иконка появится в строке меню. Автозапуск включается в настройках приложения.
Нужна macOS 13 или новее, Apple Silicon и Intel одинаково.

### Собрать из исходников

```bash
git clone https://github.com/BabkoED/climits.git
cd climits
./run-tests.sh    # проверки логики, полминуты
./build.sh        # универсальный climits.app
cp -R build/climits.app /Applications/
```

Нужны только Command Line Tools (`xcode-select --install`). Ни Xcode целиком,
ни сторонних библиотек, ни SwiftBar.

## Команда в терминале

Тот же бинарник работает как обычная команда - это удобно для statusline
и незаменимо, когда что-то не работает и нужен текст, а не значок.

```bash
/Applications/climits.app/Contents/MacOS/climits --install-cli   # ссылка в ~/bin
climits            # подробный отчёт
climits --short    # одна строка: 5ч 37% · 7д 62% · Opus 81%
climits --json     # сырой ответ API
climits --doctor   # диагностика: связка ключей, токен, срок, запрос
```

`--doctor` отвечает на вопрос «почему цифры не те»: сколько записей Claude Code
лежит в связке ключей, какая из них живая, когда истекает токен, в какой форме
пришёл ответ API и какие лимиты в нём вообще есть.

## Настройка строки меню

Два входа, один механизм: галочки собирают тот же шаблон, который можно
написать руками.

| макрос | что подставит |
|---|---|
| `{icon}` | кружок по самому нагруженному лимиту |
| `{active.left}` `{active.reset}` | до сброса у того, что упрётся первым, и когда |
| `{worst.left}` | до сброса у самого нагруженного |
| `{5h}` | процент текущего окна |
| `{5h.left}` | сколько осталось до сброса |
| `{5h.reset}` | когда сброс: `пн 03:00` |
| `{7d}` `{7d.left}` | недельный кап и сколько до сброса |
| `{opus}` `{sonnet}` `{fable}` `{haiku}` | недельный лимит модели |
| `{models}` | все модели подряд, одной буквой: `O 81% · S 12% · F 0%` |
| `{worst}` | самый нагруженный лимит |
| `{active}` | лимит, который упрётся первым |
| `{extra}` `{extra.pct}` | расход сверх лимита |
| `{money}` `{money.limit}` | во сколько обошлось окно и весь лимит |
| `{tokens}` | токены парой: `1,2м/2,2м` |

Пустой макрос убирается вместе с разделителем: модели, которой нет в тарифе,
в строке не останется висящей точки.

Деньги и токены в галочках - особый случай: галочка включает подсчёт
и показ в раскрывающемся меню, но НЕ добавляет `{money}`/`{tokens}` в трей,
даже включённая. Там всегда мало места, а сумма и пара токенов только
вытесняют остальное. В раскрывающемся меню места хватает всегда - там
показываются вообще все лимиты и строка «Сверх лимита», независимо
от галочек. Нужны деньги и в трее - дописываются вручную через свой формат,
макросы там работают как обычно.

Пока «свой формат» выключен, поле шаблона повторяет галочки: включил - и
правишь готовое, а не пустое место. Кнопка «Собрать заново из галочек»
возвращает поле к тому, что выбрано выше.

**Галочки работают как конструктор.** При включённом «своём формате» галочка
не затирает написанное, а правит его: тик добавляет свой кусок, снятие -
убирает вместе с разделителем. Порядок правится руками в самой строке.

Галочки стоят в два столбца и разделены по смыслу, а не пополам: слева то,
что борется за три-четыре знака в строке меню, справа - деньги, токены
и история, для которых в выпадающем меню места хватает всегда. Строка формата
стоит НАД галочками: они правят именно её, а править то, чего не видел,
невозможно.

Галочками собирается всё, что вообще бывает в строке: кружок, процент окна,
время до сброса, часы сброса, недельный кап, самый нагруженный лимит, что
упрётся первым, лимиты по моделям, перерасход и его процент. Руками
дописываются только отдельные модели (`{opus}`, `{sonnet}`, `{fable}`,
`{haiku}`) и деньги с токенами, если нужны наверху.

Имён макросов в окне больше нет. Таблица имён кнопками занимала пол-окна
ради случая, когда формат пишут руками, - а с полным набором галочек такого
случая почти не осталось. До 1.4 любая галочка выключала свой формат и стирала
собранную строку целиком.

Подписи «7д» перед недельным процентом нет намеренно: то, что недельный лимит
недельный, человек знает и без неё. Какое окно где, говорит отсчёт до сброса -
минуты у одного, дни у другого.

## Внешний вид

Настраивается там же, раздел «Вид». Всё задаётся текстом, поэтому менять
можно и мимо окна - через `defaults write com.babko.climits <ключ> <значение>`.

| что | ключ | по умолчанию |
|---|---|---|
| цвета трёх уровней | `colorCalm` `colorWarn` `colorAlarm` | системные |
| шкала полоской, а не знаками | `menuCapsule` | включено |
| знаки шкалы | `barFilled` `barEmpty` | `█` `░` |
| длина шкалы | `barWidth` | 10 |
| кружки слева, три через запятую | `iconSet` | `◔,◑,◕` |
| размер шрифта в строке и в меню | `fontSize` `menuFontSize` | 13, 12 |
| свой шрифт | `fontName` | системный моноширинный |
| пороги внимания и тревоги | `warnAt` `alertAt` | 50, 80 |

Пункт меню - одна строка, и второго ряда нет вовсе: полоска, имя лимита,
процент, сколько осталось, деньги и токены. До 1.6 рядов было два всегда,
и верхний уходил целиком под подпись «5-часовое окно», которую заменяет
«5ч»: ряд ради подписи удваивал высоту меню.

Часов сброса в строке больше нет. «Через 22м» и «вс 02:59» отвечают на один
вопрос двумя способами, а место в ряду стоит дороже: деньги и токены больше
нигде не сказаны, часы - сказаны отсчётом рядом. Для строки трея макрос
`{5h.reset}` остался: там отсчёта может и не быть.

Каждое число - в своей колонке: остаток, деньги, токены. У «22м» и «3д 3ч»
разная ширина, у «≈$5.20» и «≈$532» тоже, и без колонок числа гуляли бы от
строки к строке.

Колонки держат табуляторы, а не пробелы: пробел пропорционального шрифта уже
пробела моноширинного, и добивка разъезжается ровно там, где сменили шрифт.
Колонка процента - правая: у «3%» и «100%» разная ширина, по левому краю
числа стояли бы лесенкой. Ширина колонки имени считается по самому длинному
из пришедших имён, а не зашита под «Sonnet», - имя модели придумывает
Anthropic.

Шкала рисуется полоской, а не знаками. У знаков шаг заливки - целая клетка
шрифта: при четырнадцати клетках 3% и 6% дают одну и ту же картинку, а край
всегда прямой. Знаки возвращаются галочкой «полоской, а не знаками»; в
терминальном отчёте они и остаются единственным вариантом, и поля «шкала»
и «фон» правят именно их. Длина считается в тех же клетках - настройка
«длина шкалы» значит то же самое для обоих видов.

Строка «сверх лимита» стоит в тех же колонках и с той же полоской: вопрос
у неё тот же - сколько от потолка съедено. Полоски нет только там, где нет
и доли: когда перерасход выключен или потолок не задан.

Цвет принимается словом (`red`, `orange`, `teal`) или кодом (`#ff3b30`).
Пустое значение - системный цвет, он сам подстраивается под тёмную тему.
Знаком шкалы может быть что угодно, включая эмодзи.

Окно настроек прокручивается и тянется за угол. Версия и ссылка на репозиторий
прибиты к низу окна и не уезжают с прокруткой: версия нужна ровно тогда, когда
что-то пошло не так и надо сказать какую.

У полей «шкала», «фон», «кружки», «имя шрифта» и «свой формат» есть список
предложенного - с пояснением, что каждое значение даёт. Список подсказывает,
чего от поля ждут; вписать своё он не мешает. Пояснение из списка в значение
не попадает никогда, даже если выбрать мышью и тут же начать править.
Под макросами формата теперь стоит расшифровка каждого, а не только имена.

Пороги - это наша выдумка на случай, когда сервер молчит. Если в ответе есть
`severity`, слушаем его: тот, кто считает лимит, знает о нём больше нас.

## Деньги: во сколько обошёлся расход

Включено по умолчанию. Подписка меряет лимиты в процентах, а вопрос «сколько
это в деньгах» на процентах не отвечается - поэтому считаем сами.

Считается прямо, без догадок: сколько токенов прошло через видимые машины
внутри окна лимита, разложенных по моделям и по типам - вход, выход, запись
в кэш, чтение из кэша, - умноженных на прайс API. Кэш считается по своей цене,
а не по входной: у активного пользователя чтение из кэша - основная масса
токенов, и по входной цене счёт вырос бы в разы.

```
▰▰▰▰▱▱▱▱▱▱  5ч   37%  2ч 14м  ≈$12  340к
```

**Чего здесь больше нет.** До версии 1.3 рядом стояло второе число - «≈$12 из
≈$33», оценка всего лимита в деньгах. Она получалась делением своего расхода
на свой же процент, и это была ошибка не в точности, а в существе: делились
несопоставимые величины. Числитель - расход, который видим мы; знаменатель -
процент, который Anthropic считает по всему аккаунту. Замер 28.08.2026: на
маке было видно $258 при общем расходе $1182, то есть «весь лимит» занижался
вчетверо. И выглядело это число убедительнее всего остального в меню - оно
было там самым круглым.

Размер лимита Anthropic не публикует нигде: ни в тарифе, ни в справке, ни
админом в Enterprise. Честный ответ на «сколько всего» - «неизвестно».

**Прайс обновляется сам.** Раз в сутки приложение забирает
[машиночитаемый прайс LiteLLM](https://github.com/BerriAI/litellm) - он
правится в день объявления цен, - берёт оттуда старшую версию каждого
семейства и складывает разобранное в
`~/Library/Application Support/climits/pricing-remote.json`. Дата видна
в меню строкой «прайс от 29 авг». Сети нет или формат уехал - считаем по
встроенной таблице, и тогда в меню написано, что она встроенная.

Встроенная таблица - на 28.08.2026, $ за миллион токенов:

| | вход | выход | запись в кэш | чтение из кэша |
|---|---|---|---|---|
| Opus 5 | 5 | 25 | 6.25 | 0.50 |
| Fable 5 | 10 | 50 | 12.50 | 1.00 |
| Sonnet 5 | 3 | 15 | 3.75 | 0.30 |
| Haiku 4.5 | 1 | 5 | 1.25 | 0.10 |

Своя цена - корпоративная, льготная, любая - вписывается руками в
`~/Library/Application Support/climits/pricing.json`, и она сильнее обоих
источников:

```json
{ "opus": { "input": 5, "output": 25 },
  "sonnet": { "input": 2, "output": 10 } }
```

Чего нет в файле - берётся из скачанного прайса, чего нет и там - из
встроенной таблицы. Незнакомая модель считается по цене Sonnet, чтобы итог
не занулился молча.

## История и темп

Выключено по умолчанию, включается галочкой. Три строки в выпадающем меню,
и каждая отвечает на свой вопрос:

```
  7 дней ▁▃█▂▁▄▇  · сегодня 340к ≈$12
  темп 120к/ч  · к сбросу ≈$18
  при таком темпе 100% в 18:40
```

**Столбики** - «это много или как обычно». Высота считается от максимума
своей же недели: абсолюта здесь нет, лимит в токенах никто не публикует.
Пустой день рисуется точкой, а не самым низким блоком - «ничего» и
«немного» это разные ответы.

**Темп** - сколько токенов в час прошло за последний час, и во что обойдётся
окно к сбросу, если так и продолжать. Это не прогноз лимита: сколько его
всего, мы по-прежнему не знаем.

**Прогноз** - вот он как раз про лимит, и в нём нет ни одного предположения
о размере. Процент приходит от сервера каждые пять минут, у него есть
наклон: было 40%, стало 52% за час - значит 12% в час, и до сотни четыре
часа. Проценты делятся на проценты. Если сброс окна раньше - так и написано:
«при таком темпе до сброса не упрёшься».

Замеры процента копятся всегда, даже с выключенной галочкой: иначе включить
её и увидеть пустоту значило бы ждать час, пока наберётся наклон. Файл -
`~/Library/Application Support/climits/history.json`, восемь суток, порядка
двух тысяч строк.

Всё посуточное считается тем же проходом по файлам, что и деньги: передать
восемь границ окна вместо двух стоит столько же, сколько две.

## Второй аккаунт на этой машине

Второй аккаунт со своим `CLAUDE_CONFIG_DIR` пишет расшифровки мимо
`~/.claude/projects`. Лимит при этом общий, а расход мы видели только
домашний - ошибка той же природы, что и работа со второй машины, только
ближе. В настройках, в «Ещё каталоги на этой машине», пути пишутся через
пробел:

```
~/work/.claude/projects ~/personal/.claude/projects
```

Сколько каталогов в счёте, видно в меню строкой «по расшифровкам только
этой машины и ещё 1 катал.».

## Уведомления

Выключены по умолчанию. Включаются вместе с порогом в процентах.

Сообщение приходит один раз на пересечение, а не каждые пять минут, пока
процент держится выше порога. После сброса окна взводится заново - иначе за
неделю оно пришло бы однажды и больше никогда.

## Когда нет ни сети, ни кэша

Приложение читает локальные расшифровки Claude Code и показывает, сколько
запросов и токенов прошло за последние пять часов и во сколько это обошлось
бы по прайсу. Это **расход, а не остаток лимита**, и подписано именно так:
работа с других машин сюда не попадает, а проценты сервер считает по всему
аккаунту.

## Откуда данные

```
GET https://api.anthropic.com/api/oauth/usage
Authorization: Bearer <токен из связки ключей>
```

Тот же эндпоинт, который Claude Code запрашивает для `/usage`. Токен читается
из системной связки ключей утилитой `/usr/bin/security` - туда его положил сам
Claude Code при логине. Токен не сохраняется на диск и не уходит никуда, кроме
`api.anthropic.com`.

Эндпоинт **не документирован**. Он уже менял форму ответа, поэтому разбор идёт
двумя путями сразу - массив `limits` и объекты верхнего уровня, - и приложение
переживёт переход с одной формы на другую.

## Когда API недоступен

Отдельно продуманная часть, потому что именно здесь такие индикаторы обычно
показывают пустоту.

- Ответ кэшируется; по умолчанию запрос не чаще раза в 5 минут
- HTTP 429 - пауза на 15 минут, на экране остаются последние цифры с пометкой `~`
- Нет сети - то же самое: последние известные цифры и строка «данные от 14:20»
- Данные старше суток не показываются вовсе
- HTTP 401/403 - единственный случай, когда старые цифры скрываются: проблема
  требует действия, и показывать спокойные проценты значит её отложить
- В связке ключей нередко лежит несколько записей Claude Code, и `security`
  отдаёт первую попавшуюся - вполне возможно, битую. Приложение собирает все
  пригодные записи, пробует самую свежую, и только если сервер ответил 401 -
  берёт следующую. Это реальный случай, а не предосторожность: у человека
  с двумя записями индикатор молчал, пока рабочий токен лежал рядом

## Про 429

Эндпоинт лимитирует запросы жёстко и без объяснений: в трекере claude-code
есть [issue #30930](https://github.com/anthropics/claude-code/issues/30930)
и [issue #31637](https://github.com/anthropics/claude-code/issues/31637) -
постоянный 429 с `retry-after: 0`, оба закрыты без ответа Anthropic. Отсюда
и вся возня с кэшем, паузой и показом старых цифр: без неё индикатор такого
рода регулярно превращается в пустой значок.

Ходит мнение, что дело в заголовке `User-Agent`: мол, без значения вида
`claude-code/<версия>` запросы попадают в отдельный, куда более жёсткий бакет.
**Первоисточниками это не подтверждается** - в обоих issues User-Agent
не упоминается вовсе. Поэтому climits по умолчанию представляется своим
именем.

Поля User-Agent в настройках нет: менять его полезно ровно в этом одном
редком случае, а стоило оно строки в окне и вопроса «а что сюда писать».
Запасной выход остался и работает без пересборки:

```bash
defaults write com.babko.climits userAgent "claude-code/1.0.0"
```

## Токены: сколько их в тарифе

Никто не говорит. Ни справка Anthropic, ни тариф, ни админ в Enterprise -
лимит везде выражен процентами.

До версии 1.3 приложение пыталось это вычислить: делило свой расход на свой
же процент и показывало «1,2м/2,2м». Число убрано. Числитель там - расход
машин, которые мы читаем, знаменатель - процент по всему аккаунту; это
величины из разных множеств, и деление давало не оценку с погрешностью,
а число без смысла. На замере 28.08.2026 «весь лимит» занижался вчетверо.

Теперь галочка «Токены» показывает только измеренное: сколько прошло за
окно. Ответ на «а сколько всего» - «неизвестно», и это честный ответ.

Что вместо: столбики за неделю отвечают на «это много или как обычно»,
а прогноз по наклону процента - на «упрусь ли раньше, чем сбросится».
Оба обходятся без размера лимита, см. «История и темп».

## Вторая машина

Процент лимита сервер Anthropic считает по всему аккаунту. А токены и деньги
climits считает сам - по файлам `~/.claude/projects` **той машины, где
запущен**. Если работа идёт ещё и по ssh на сервере, локальный счёт видит
меньшую часть расхода.

Замер 28.08.2026: за одно и то же недельное окно мак насчитал $258,
а сервер - $924. Это не разные лимиты, это два куска одного расхода.

В настройках, раздел «Вторая машина», выбирается адрес. Это выпадающий
список: в него подставлено всё, что записано в `~/.ssh/config`, - адрес
выбирается, а не набирается по памяти. Нет записей - вписывается целиком,
вида `user@адрес`. Приложение выполняет там тот же разбор и складывает
с местным.

Кнопка «Проверить» показывает, что оттуда приехало, а при отказе называет
причину словами: «ключ этой машины не пущен на ту сторону», «хост
незнакомый», «на той стороне нет python3». Незнакомую ошибку не переводит -
отдаёт как есть, потому что выдуманное объяснение хуже непонятного.

Что нужно на той стороне: `python3` и вход по ключу без пароля. Пароль
спросить негде - окна для этого нет, поэтому `BatchMode=yes`, и незнакомый
хост даёт честную ошибку, а не молчаливый ноль. Зайди на него из терминала
один раз, чтобы он попал в `known_hosts`.

## Обновление

«Проверить обновления» внизу меню. Приложение смотрит последний релиз,
и если он новее - качает `climits.zip`, **сверяет SHA-256 с суммой из текста
релиза**, распаковывает, подменяет себя и перезапускается.

Сверка суммы здесь не формальность: без неё автообновление было бы дырой
шире той, что оно закрывает. Нет суммы в тексте релиза - приложение
отказывается обновляться само и открывает страницу.

Сверка суммы - единственный шаг, который отказывает молча. Всё, что после
неё, только спрашивает. Причина измерена: проверку выполняет **та версия,
которая уже стоит**, и ошибка в позднем шаге запирает обновление навсегда -
выпуск новой версии её не чинит. Так и вышло в 1.2.1: у `codesign` нет ключа
`--quiet`, а проверить это на Linux нечем, codesign там не существует.

Раз в сутки оно проверяет тихо: находит новую версию - ставит строку в меню
и ничего не качает без нажатия. Сборку из исходников (`dev`) релизом
не подменяет.

## Как это проверяется

`./run-tests.sh` гоняет разбор ответа API на обеих известных формах,
на мусоре вместо JSON и на сборке строки меню. Это не показуха: именно там
живут ошибки, которых не видно глазами - сумма, завышенная ровно в сто раз,
выглядит так же убедительно, как правильная.

CI на каждый коммит прогоняет эти проверки и собирает приложение на настоящем
macOS. По тегу `v*` сборка попадает в релизы.

## Чего пока нет

Иконки приложения. Подписи сертификатом Apple - отсюда и правый клик при
первом запуске, и вопрос про связку ключей после каждого обновления:
ad-hoc подпись у каждой сборки своя.

[claude-limit-bar](https://github.com/akiril1/claude-limit-bar) - оттуда взято
и проверено на нём же:

- поле `severity` как источник уровня тревоги вернее собственных порогов
- мысль, что индикатору незачем зависеть от SwiftBar

## English

macOS menu bar app showing your Claude usage limits - the same numbers as
`/usage` inside Claude Code, without having Claude Code open.

Build: `./build.sh` (needs Command Line Tools, macOS 13+), then copy
`build/climits.app` to `/Applications`. No dependencies, no SwiftBar.

The same binary works as a CLI: `--short`, `--full`, `--json`, `--doctor`.
UI language follows the system (Russian or English).

Data comes from the undocumented `api.anthropic.com/api/oauth/usage` endpoint
using the OAuth token Claude Code stored in your keychain. Nothing is written
to disk except the cached response, nothing is sent anywhere else.
