# climits

Лимиты Claude в строке меню macOS. Те же цифры, что показывает `/usage`
внутри Claude Code, только видны всегда и без запуска Claude Code.

> **Статус:** первая версия. Логика разбора покрыта проверками (`./run-tests.sh`),
> сборка приложения идёт на настоящем macOS в CI - значок сверху показывает,
> прошла ли она. Если что-то не так на твоей машине, заведи issue.


## Что показывает

В строке меню - то, что выберешь сам: процент текущего окна, время до сброса,
недельный кап, лимиты по каждой модели (Opus, Sonnet, Fable), потраченное сверх
лимита в деньгах. Кружок слева меняется по самому нагруженному лимиту, даже
если в тексте показан другой - чтобы короткая строка не скрывала проблему.

В выпадающем меню - все лимиты сразу: шкала, процент, время до сброса,
пометка `▸` у того, который упрётся первым. Отдельной строкой - расход сверх
лимита и персональный месячный потолок, если он задан.

## Установка

Готовая сборка - в [релизах](https://github.com/BabkoED/climits/releases).
Ничего ставить и собирать не нужно. Отдельная инструкция для тех, кто просто
хочет поставить и пользоваться: [INSTALL.md](INSTALL.md).

1. Скачать `climits.zip`, распаковать
2. Перетащить `climits.app` в «Программы»
3. Первый запуск - **правый клик по приложению → «Открыть» → «Открыть»**

Третий шаг обязателен ровно один раз. macOS скажет, что разработчик не
подтверждён: приложение не подписано сертификатом Apple, потому что сертификат
стоит денег и выдаётся на человека. Обычный двойной клик после этого работает.

Кому привычнее командой:

```bash
xattr -dr com.apple.quarantine /Applications/climits.app
```

Иконка появится в строке меню. Автозапуск включается в настройках приложения.
Нужна macOS 13 или новее, Apple Silicon и Intel одинаково.

### Собрать из исходников

```bash
git clone https://github.com/BabkoED/climits.git
cd climits
./run-tests.sh    # проверки логики, полминуты
./build.sh        # универсальный climits.app
cp -R build/climits.app /Applications/
```

Нужны только Command Line Tools (`xcode-select --install`). Ни Xcode целиком,
ни сторонних библиотек, ни SwiftBar.

## Команда в терминале

Тот же бинарник работает как обычная команда - это удобно для statusline
и незаменимо, когда что-то не работает и нужен текст, а не значок.

```bash
/Applications/climits.app/Contents/MacOS/climits --install-cli   # ссылка в ~/bin
climits            # подробный отчёт
climits --short    # одна строка: 5ч 37% · 7д 62% · Opus 81%
climits --json     # сырой ответ API
climits --doctor   # диагностика: связка ключей, токен, срок, запрос
```

`--doctor` отвечает на вопрос «почему цифры не те»: сколько записей Claude Code
лежит в связке ключей, какая из них живая, когда истекает токен, в какой форме
пришёл ответ API и какие лимиты в нём вообще есть.

## Настройка строки меню

Два входа, один механизм: галочки собирают тот же шаблон, который можно
написать руками.

| макрос | что подставит |
|---|---|
| `{icon}` | кружок по самому нагруженному лимиту |
| `{5h}` | процент текущего окна |
| `{5h.left}` | сколько осталось до сброса |
| `{5h.reset}` | когда сброс: `пн 03:00` |
| `{7d}` | недельный кап |
| `{opus}` `{sonnet}` `{fable}` `{haiku}` | недельный лимит модели |
| `{models}` | все модели подряд |
| `{worst}` | самый нагруженный лимит |
| `{active}` | лимит, который упрётся первым |
| `{extra}` `{extra.pct}` | расход сверх лимита |
| `{money}` `{money.limit}` | во сколько обошлось окно и весь лимит |

Пустой макрос убирается вместе с разделителем: модели, которой нет в тарифе,
в строке не останется висящей точки.

## Внешний вид

Настраивается там же, раздел «Вид». Всё задаётся текстом, поэтому менять
можно и мимо окна - через `defaults write com.babko.climits <ключ> <значение>`.

| что | ключ | по умолчанию |
|---|---|---|
| цвета трёх уровней | `colorCalm` `colorWarn` `colorAlarm` | системные |
| знаки шкалы | `barFilled` `barEmpty` | `█` `░` |
| длина шкалы | `barWidth` | 14 |
| кружки слева, три через запятую | `iconSet` | `◔,◑,◕` |
| размер шрифта в строке и в меню | `fontSize` `menuFontSize` | 13, 12 |
| свой шрифт | `fontName` | системный моноширинный |
| пороги внимания и тревоги | `warnAt` `alertAt` | 50, 80 |
| пункты меню в две строки | `twoLineRows` | да |

Цвет принимается словом (`red`, `orange`, `teal`) или кодом (`#ff3b30`).
Пустое значение - системный цвет, он сам подстраивается под тёмную тему.
Знаком шкалы может быть что угодно, включая эмодзи.

Пороги - это наша выдумка на случай, когда сервер молчит. Если в ответе есть
`severity`, слушаем его: тот, кто считает лимит, знает о нём больше нас.

## Деньги: во сколько это обошлось бы по прайсу

Выключено по умолчанию, включается в настройках. Подписка меряет лимиты
в процентах, а вопрос «а сколько это в деньгах» на процентах не отвечается -
поэтому считаем сами.

Считается так. Прямо, без догадок: сколько токенов прошло через эту машину
внутри окна лимита, разложенных по моделям и по типам - вход, выход, запись
в кэш, чтение из кэша, - умноженных на прайс API. Кэш считается по своей цене,
а не по входной: у активного пользователя чтение из кэша - основная масса
токенов, и по входной цене счёт вырос бы в разы.

И только один шаг догадки: если этот трафик израсходовал 10% лимита, то весь
лимит стоит примерно вдесятеро больше. В меню это выглядит так:

```
5-часовое окно                       37%
   ████░░░░░░░░░░  через 2ч 14м · ≈$12 из ≈$33
```

**Чему здесь верить.** «≈$12» - прямой счёт по токенам, он точен настолько,
насколько точен прайс. «≈$33» - экстраполяция, и она верна ровно в той мере,
в какой расшифровки на этой машине покрывают весь расход аккаунта. Работа
с другого ноутбука сюда не попадает, и тогда оценка занижена. Ниже 5%
израсходованного экстраполяция не показывается вовсе: на одном проценте
деление умножает любую погрешность на сто.

Прайс встроен на 28.08.2026 ($ за миллион токенов):

| | вход | выход | запись в кэш | чтение из кэша |
|---|---|---|---|---|
| Opus 5 | 5 | 25 | 6.25 | 0.50 |
| Fable 5 | 10 | 50 | 12.50 | 1.00 |
| Sonnet 5 | 3 | 15 | 3.75 | 0.30 |
| Haiku 4.5 | 1 | 5 | 1.25 | 0.10 |

Цены меняются, и зашитая таблица однажды начнёт врать молча. Поэтому она
перекрывается файлом `~/Library/Application Support/climits/pricing.json`:

```json
{ "opus": { "input": 5, "output": 25 },
  "sonnet": { "input": 2, "output": 10 } }
```

Чего нет в файле - берётся из встроенной таблицы. Незнакомая модель считается
по цене Sonnet, чтобы итог не занулился молча.

## Уведомления

Выключены по умолчанию. Включаются вместе с порогом в процентах.

Сообщение приходит один раз на пересечение, а не каждые пять минут, пока
процент держится выше порога. После сброса окна взводится заново - иначе за
неделю оно пришло бы однажды и больше никогда.

## Когда нет ни сети, ни кэша

Приложение читает локальные расшифровки Claude Code и показывает, сколько
запросов и токенов прошло за последние пять часов и во сколько это обошлось
бы по прайсу. Это **расход, а не остаток лимита**, и подписано именно так:
работа с других машин сюда не попадает, а проценты сервер считает по всему
аккаунту.

## Откуда данные

```
GET https://api.anthropic.com/api/oauth/usage
Authorization: Bearer <токен из связки ключей>
```

Тот же эндпоинт, который Claude Code запрашивает для `/usage`. Токен читается
из системной связки ключей утилитой `/usr/bin/security` - туда его положил сам
Claude Code при логине. Токен не сохраняется на диск и не уходит никуда, кроме
`api.anthropic.com`.

Эндпоинт **не документирован**. Он уже менял форму ответа, поэтому разбор идёт
двумя путями сразу - массив `limits` и объекты верхнего уровня, - и приложение
переживёт переход с одной формы на другую.

## Когда API недоступен

Отдельно продуманная часть, потому что именно здесь такие индикаторы обычно
показывают пустоту.

- Ответ кэшируется; по умолчанию запрос не чаще раза в 5 минут
- HTTP 429 - пауза на 15 минут, на экране остаются последние цифры с пометкой `~`
- Нет сети - то же самое: последние известные цифры и строка «данные от 14:20»
- Данные старше суток не показываются вовсе
- HTTP 401/403 - единственный случай, когда старые цифры скрываются: проблема
  требует действия, и показывать спокойные проценты значит её отложить
- В связке ключей нередко лежит несколько записей Claude Code, и `security`
  отдаёт первую попавшуюся - вполне возможно, битую. Приложение собирает все
  пригодные записи, пробует самую свежую, и только если сервер ответил 401 -
  берёт следующую. Это реальный случай, а не предосторожность: у человека
  с двумя записями индикатор молчал, пока рабочий токен лежал рядом

## Про 429

Эндпоинт лимитирует запросы жёстко и без объяснений: в трекере claude-code
есть [issue #30930](https://github.com/anthropics/claude-code/issues/30930)
и [issue #31637](https://github.com/anthropics/claude-code/issues/31637) -
постоянный 429 с `retry-after: 0`, оба закрыты без ответа Anthropic. Отсюда
и вся возня с кэшем, паузой и показом старых цифр: без неё индикатор такого
рода регулярно превращается в пустой значок.

Ходит мнение, что дело в заголовке `User-Agent`: мол, без значения вида
`claude-code/<версия>` запросы попадают в отдельный, куда более жёсткий бакет.
**Первоисточниками это не подтверждается** - в обоих issues User-Agent
не упоминается вовсе. Поэтому climits по умолчанию представляется своим
именем. Значение меняется в настройках, без пересборки: если 429 мешает,
можно проверить гипотезу на себе и рассказать, что вышло.

## Как это проверяется

`./run-tests.sh` гоняет разбор ответа API на обеих известных формах,
на мусоре вместо JSON и на сборке строки меню. Это не показуха: именно там
живут ошибки, которых не видно глазами - сумма, завышенная ровно в сто раз,
выглядит так же убедительно, как правильная.

CI на каждый коммит прогоняет эти проверки и собирает приложение на настоящем
macOS. По тегу `v*` сборка попадает в релизы.

## Чего пока нет

Иконки приложения. Автообновления. Подписи сертификатом Apple - отсюда
и правый клик при первом запуске.

## Благодарности

[claude-limit-bar](https://github.com/akiril1/claude-limit-bar) - оттуда взято
и проверено на нём же:

- настоящая форма массива `limits`: `kind` со значениями `session` /
  `weekly_all` / `weekly_scoped`, а имя модели в `scope.model.display_name`.
  Наш разбор искал имя модели не там, и все модельные лимиты слипались в один
- перечисление записей связки ключей через `SecItemCopyMatching`: запрос
  атрибутов не поднимает диалог авторизации, в отличие от разбора вывода
  `security dump-keychain`
- растущая пауза после 429 вместо плоской, и нижний порог между запросами
- поле `severity` как источник уровня тревоги вернее собственных порогов
- мысль, что индикатору незачем зависеть от SwiftBar

## English

macOS menu bar app showing your Claude usage limits - the same numbers as
`/usage` inside Claude Code, without having Claude Code open.

Build: `./build.sh` (needs Command Line Tools, macOS 13+), then copy
`build/climits.app` to `/Applications`. No dependencies, no SwiftBar.

The same binary works as a CLI: `--short`, `--full`, `--json`, `--doctor`.
UI language follows the system (Russian or English).

Data comes from the undocumented `api.anthropic.com/api/oauth/usage` endpoint
using the OAuth token Claude Code stored in your keychain. Nothing is written
to disk except the cached response, nothing is sent anywhere else.
